# Vercel serverless fetch with Google Drive handoff, replacing the routine's direct fetch

We hit a hard blocker in issue #2: the Claude Code cloud routine's sandbox blocks outbound HTTP to `hn.algolia.com` regardless of network policy setting, so the direct-fetch half of ADR-0001's hybrid design can't run inside the routine. We moved the fetch + keyword pre-filter (previously invoked by the routine, per ADR-0001) into a Vercel serverless function instead, since Vercel has no such egress restriction. The function runs on a daily Vercel Cron schedule, writes the result — the Fetch Payload — to Google Drive, then pushes the routine via its API trigger, passing success/failure explicitly in the trigger payload rather than relying on Drive file state. The routine's own cron trigger is removed; the API trigger is now the sole path in. The routine reads the Fetch Payload from Drive via its Google Drive MCP connector — MCP connector traffic routes through Anthropic's backend rather than the sandbox's network boundary, so it isn't subject to the same egress block.

This keeps the fetch + pre-filter logic in one place (Python, in `src/news_assistant/`, now also deployed as a thin Vercel wrapper) rather than duplicating it, and avoids provisioning any paid infrastructure — Vercel Hobby, the Google Drive API, and the email step are all free at this volume.

The trade-off: the pipeline now depends on three externally-provisioned pieces (Vercel project, Google OAuth credentials for Drive, an email-sending credential) instead of one, and a Drive-read failure inside the routine is a new failure mode ADR-0001 didn't have to consider.

**Correction (2026-08-17):** two assumptions above didn't survive contact with a real run. (1) The Google Drive MCP connector cannot read the Fetch Payload — it's a Google Docs/Sheets/Slides picker and returns zero results for a plain `.json` file. The routine now reads via the Drive REST API directly (`drive_cli.py`), the same OAuth token the write side uses. (2) SMTP + a Gmail App Password cannot work at all from the routine's cloud sandbox — it only permits an HTTPS proxy path, not raw TCP sockets, so `smtplib`'s socket connection failed outright regardless of credentials. We switched to the Resend HTTP API (plain HTTPS, static API key, no OAuth lifecycle), which also sidesteps the Gmail API's 7-day sensitive-scope token expiry without needing SMTP's now-proven-broken transport.
